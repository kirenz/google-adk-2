8  Composing agents with deterministic work

Multiple agents are useful when separate tasks need different instructions, tools, or output contracts. A larger number of agents is not a quality metric. The course’s mixed graph uses one focused extraction agent, deterministic arithmetic, and a deterministic presentation function. Each stage has a distinct responsibility that can be observed and tested.

8.1 The order-analysis graph

An order request such as “Calculate 4 bicycles at 500 EUR each” combines language interpretation and exact arithmetic. The extraction agent identifies the unit price and quantity. Python computes their product. A Python function formats the result without changing the calculation.

The implementation is in examples/agent_workflow/agent.py. It uses a Pydantic order schema at the handoff from model output to Python. This schema specifies nullable unit-price and quantity fields with strict numeric constraints. Missing inputs are represented as null; the Python step returns needs_input and the presentation step names the missing field without calculating a total. Negative values are rejected. The arithmetic function separately validates complete inputs.

Selecting agent_workflow runs the mixed graph. This example requires valid Gemini access because the extraction node uses a model. The deterministic middle step must not be skipped even when the model knows simple multiplication. The trace separates the proposed order from the computed total and the final explanation.

8.2 Three composition choices

Pattern Who controls the next step? Appropriate example
Agent with function tools Model chooses an available tool call Flexible calculation request
Graph containing agents and functions Executable edges determine order Extract, calculate, present
Agent delegation or agent-as-tool Coordinator requests specialist work Different specialist capabilities

An agent used as a tool returns a result to its caller. A delegated conversation can transfer control to another agent. These differ from a fixed graph that schedules each node. The official multi-agent documentation describes composition patterns; their runtime behavior must be checked in the chosen ADK version.

The earlier SequentialAgent, ParallelAgent, and LoopAgent template workflows remain useful vocabulary for ADK materials. This book teaches the graph-based Workflow explicitly rather than presenting those templates as the new graph API. A sequential edge list also does not imply parallel execution.

8.3 Boundaries between specialists

A specialist should receive the data needed for its task. A hypothetical presentation agent would need the validated order and total, not the API key or an unrelated conversation. A critic may assess clarity, but its approval must not override a failed arithmetic or database check. Model judges have uncertainty and cannot replace deterministic validation of facts that Python can calculate exactly.

8.4 Exercise: trace an ambiguous order

Three cases are compared: a complete order, an order with missing quantity, and an order with an invalid negative quantity. The record identifies whether extraction succeeds, whether deterministic validation rejects the value, and whether the final response reports that limitation.

Expected result: complete inputs reach presentation with correct totals; invalid or incomplete inputs do not become fabricated successful orders.

Success criteria: each number in the final answer can be traced to validated inputs and Python arithmetic. The supplied graph requests missing input but does not accumulate partial orders across turns. The next request must include the complete order. Extending it with stateful clarification requires an explicit state contract, bounded routing, and a stopping condition. The offline fake-model test verifies the missing-input path without assuming that a live model always extracts values correctly.
